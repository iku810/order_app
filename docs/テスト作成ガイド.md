# テスト作成ガイド

本ドキュメントは、ロジックの単体テストのみを対象とする。  
UI / Widget テストは含めない。

# 1. 基本方針

- テスト対象は **domain / application / data / infrastructure のロジック**
- UIはテスト対象外
- 外部通信・SDKはモック化する
- テストは lib 構造を ミラーする
- モックは [mockito](https://pub.dev/packages/mockito) を利用する

# 2. テスト対象ごとの責務

## 2.1 Domain（Entity / VO）

### テストすること

- 不変条件
- バリデーション
- 値オブジェクトの等価性
- ビジネスルール

### テストしないこと

- 外部通信
- Repository実装

## 前提

- 純粋なロジックのみをテストする

## 2.2 UseCase（application層）

### テストすること

- Repositoryが正しく呼ばれているか
- ビジネスフローが正しいか
- 例外ハンドリング

### テストしないこと
- Repository実装
- DTO → Entity 変換など

### 前提

- RepositoryはMockにする
- 外部I/Oは行わない

---

## 2.3 RepositoryImpl（data層）

RepositoryImplは「外界とDomainの境界」である。

### テストすること

- DTO → Entity の変換
- 正しいパラメータで下位APIを呼んでいるか
- Domain契約に沿った例外変換
- Domain契約に沿った型・戻り値・挙動を守っているか

### テストしないこと

- HTTP通信の正しさ
- フレームワーク挙動

### 前提
- 下位APIはモック化する
- DTOやAPIレスポンスは任意のダミーデータで用意する

## RepositoryImpl テストテンプレート

### 成功パターン

```dart
test('正常系: User を返す', () async {
  final mockApi = MockApiClient();
  final repository = UserRepositoryImpl(mockApi);

  when(mockApi.get('/users/1')).thenAnswer(
    (_) async => {
      'id': '1',
      'name': 'John',
    },
  );

  final result = await repository.fetchUser('1');

  expect(result.id, '1');
  expect(result.name, 'John');
});
```

#### 検証ポイント
- 正しいパスでAPIを呼んでいる
- DTO → Entity が正しく変換されている
- nullを返していない

### 例外変換
```dart
test('NotFoundException を UserNotFoundFailure に変換する', () async {
  final mockApi = MockApiClient();
  final repository = UserRepositoryImpl(mockApi);

  when(mockApi.get(any)).thenThrow(NotFoundException());

  expect(
    () => repository.fetchUser('1'),
    throwsA(isA<UserNotFoundFailure>()),
  );
});
```

#### 検証ポイント
- 正しいパスでAPIを呼んでいる
- Domain契約に沿って例外が返っているか
- nullを返していない
