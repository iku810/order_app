## 📁 各フォルダの役割

### infrastructure（技術基盤層）

| パス                     | 役割             | 責務                                       |
| ------------------------ | ---------------- | ------------------------------------------ |
| lib/infrastructure       | アプリの技術基盤 | 外部I/O・通信・技術例外の定義              |
| infrastructure/network   | 通信処理         | APIクライアント、InterceptorなどのHTTP実装 |
| infrastructure/exception | 技術例外定義     | AppExceptionなどの技術由来の例外           |

制約：

- infrastructureは純粋な技術基盤とする
- data層のみがinfrastructureに依存できる（shared や domain が直接依存してはいけない）。

### shared（横断ドメイン）

| パス                        | 役割                 | 責務                                  |
| --------------------------- | -------------------- | ------------------------------------- |
| lib/shared                  | アプリ全体の業務概念 | 複数featureから参照される共通ドメイン |
| shared/feature_nameA/domain | 横断的な業務モデル   | Entity、VO、Repository抽象            |
| shared/feature_nameA/data   | 横断ドメインの実装   | Repository実装、DTO定義               |

制約：

- 横断ドメインのみを持つ
- UIを持たない
- UseCaseを持たない
- featuresに依存しない

### features（ユースケース単位）

| パス                               | 役割                   | 責務                       |
| ---------------------------------- | ---------------------- | -------------------------- |
| lib/features                       | 機能単位のモジュール群 | 画面・操作単位の機能       |
| features/feature_nameB/domain      | 機能固有の業務概念     | Entity、VO、Repository抽象 |
| features/feature_nameB/application | ユースケース層         | UseCase（操作の定義）      |
| features/feature_nameB/data        | 実装詳細               | Repository実装、DTO        |
| features/feature_nameB/ui          | 表示層                 | View、ViewModel            |

## 依存関係ルール

## モジュール間の依存方向

- features は shared に依存してよい
- shared は features に依存してはいけない
- data層のみがinfrastructure に依存できる

## feature内部の依存方向

- 以下の依存は許可する
  - ui → application
  - application → domain
  - data → domain
  - data → infrastructure
- 以下の依存は禁止する
  - domain → application
  - domain → data
  - domain → infrastructure
  - shared → features
